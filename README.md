# mysh

Учебный проект: командный интерпретатор (shell) на языке C. Эталон
поведения — bash.

## Состояние

Реализована вся база из ТЗ:

- **лексер** — слова и операторы, кавычки, экранирование, комментарии;
- **парсер** — вся грамматика (простые команды, перенаправления, конвейеры,
  `&&` / `||`, списки, подоболочки) в дерево команд;
- **исполнитель** — внешние программы, перенаправления `<` `>` `>>`,
  конвейеры, `;` `&&` `||`, подоболочки, запуск в фоне `&`;
- **встроенные команды** — `cd`, `pwd`, `echo`, `help`, `exit`, `jobs`, `fg`,
  `bg`, `kill`, `wait`;
- **управление заданиями и сигналы** — группы процессов, терминал,
  Ctrl-C / Ctrl-Z, уведомления о фоновых заданиях;
- **режимы запуска** — интерактивный, `-c`, `< файл`, а также отладочные
  `--dump-tokens` и `--dump-ast`.

Подробности, отличия от bash и ограничения — в [report.md](report.md).

## Сборка

Нужны `gcc` (или `clang`), `make`, Linux (проверялось в WSL).

```bash
make          # релизная сборка -> ./mysh
make debug    # со sanitizers (address, undefined) -> ./mysh-debug
make test     # все тесты (сверка с bash, интерактивный режим)
make clean    # удалить собранные файлы
```

## Запуск

```bash
./mysh                                  # интерактивный режим
./mysh -c 'echo a | wc -l; (cd /; pwd)' # выполнить одну строку
./mysh < script.txt                     # команды из файла
./mysh --dump-tokens -c 'echo "a  b" | wc -l'    # токены одной строки
./mysh --dump-ast    -c '(echo a; echo b) | wc'  # дерево команд одной строки
```

Пример интерактивного сеанса:

```
mysh> sleep 100
^Z
[1]+  Stopped                 sleep 100
mysh> bg
[1]+ sleep 100 &
mysh> jobs
[1]+  Running                 sleep 100 &
mysh> kill %1
mysh>
[1]+  Terminated              sleep 100
```

Коды возврата: код последней команды; `1` — нехватка памяти или неверные
аргументы, `2` — синтаксическая ошибка, `126` — команду нельзя выполнить,
`127` — команда не найдена, `128 + N` — завершение по сигналу `N`.
Приглашение `mysh> ` выводится, если ввод идёт из терминала; недописанная
команда (незакрытая кавычка, `\` в конце строки) дочитывается со следующей
строки.

## Тесты

```bash
make test                              # на обычной сборке
bash tests/run_tests.sh ./mysh-debug   # на сборке с sanitizers
```

Файлы тестов: `tests/syntax.txt` (принято / отвергнуто, с проверкой по
`bash -n`), `tests/golden.txt` (точный вывод `--dump-tokens` и `--dump-ast`),
`tests/run_tests.sh` (запуск; выполнение команд сверяется с `bash`;
интерактивный режим и управление заданиями проверяются через псевдотерминал
утилитой `script`).

## Структура

```
src/
├── lexer.h, lexer.c           лексер: строка → token_list
├── ast.h,   ast.c             дерево команд: типы, память, печать
├── parser.h, parser.c         парсер: token_list → дерево (рекурсивный спуск)
├── executor.h, executor.c     исполнитель: процессы, каналы, списки, подоболочки
├── redirect.h, redirect.c     перенаправления < > >>
├── builtins.c                 встроенные команды
├── jobs.h,  jobs.c            таблица заданий, сигналы, ожидание, терминал
├── shell.h, shell.c           главный цикл интерпретатора
├── mysh_getline.h, .c         чтение строки из потока
└── main.c                     точка входа, разбор аргументов
tests/                         тесты
Makefile
report.md                      отчёт о работе
```
